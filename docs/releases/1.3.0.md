This is the **stable 1.3.0 minor release** of `@wh1teee/mui-phone-input`. It
lets products put the country list in their own sheet, choose what the trigger
shows, follow a late default country and search countries in Japanese.

## What is new

- Base UI/shadcn export `PhoneCountryTrigger` and `PhoneCountryList`, the two
  parts the built-in popover is now made of. The list can live in a host dialog
  or bottom sheet and closes from `onSelect(country)`, which runs after the
  selection is applied. It is named by `messages.dialogTitle`, owns its keyboard
  model, marks and scrolls to the selected row, and mirrors
  `aria-activedescendant` when focused itself. `autoFocusSearch` (`true`,
  `false` or `'fine-pointer'`) keeps the on-screen keyboard closed on touch
  devices.
- Both parts use the `locale` and `messages` given to `usePhoneInput` (new
  `messages` option, also a top-level `PhoneInput` prop); `PhoneInputState`
  gains optional `locale` and `messages`.
- Base UI/shadcn `PhoneInput` gains `renderCountrySelector`, which replaces only
  the country presentation and receives `phone`, `triggerProps` (including
  `countrySelector.triggerProps`), `listProps`, `defaultSelector` and
  `focusInput`.
- `triggerContent` on both renderers: `'auto'`, `'calling-code'`,
  `'country-code'`, `'both'` or a render function. `'auto'` keeps the current
  rendering.
- While a field is untouched (empty, never edited, nothing picked), the selected
  country follows a changed `defaultCountry`, reported by `onCountryChange` with
  reason `default`. A late value that is missing, empty or not a country of the
  loaded metadata is ignored.
- `@wh1teee/mui-phone-input/locales/ja` adds the Japanese locale with
  `searchAliases`: kana readings of every country name written with kanji. The
  new `searchAliases` option of the country list accepts them, so 日本 is found
  by `にほん`. Search folds hiragana to katakana, so `べらるーし` finds ベラルーシ
  before IME conversion.
- `shadcn.css` lets off-screen option rows skip layout and paint
  (`content-visibility: auto` with a single-line intrinsic size); option rows use
  `box-sizing: border-box`.

## Behavior changes

- Base UI/shadcn: the country trigger's accessible name always contains the
  selected country and calling code through the new optional `triggerLabel`
  message, present in every locale. Without a host label it was "Select country"
  and is now "Select country. Belarus, BY, +375", like the MUI trigger. A host
  `triggerProps['aria-label']` used to replace the name and is now its prefix
  ("Country. Belarus, BY, +375"). MUI is unchanged: a host `aria-label` is still
  the whole name.
- Base UI/shadcn: the standalone `PhoneInputCountrySelector` takes `locale` and
  `messages` from `phone` when its own props omit them; 1.2.1 used English.
- The built-in Base UI/shadcn popover centres the selected row when it opens.
- `triggerContent: 'calling-code'` draws `+375` in national mode; in
  international modes, where the input already starts with the code, it falls
  back to `'auto'`.
- The shadcn trigger chevron also turns on `aria-expanded="true"`, for triggers
  rendered outside Base UI.

## Stable 1.0 compatibility retained

The stable 1.0 API remains compatible: React Hook Form (RHF), Zod, server,
locale, flag, and renderer-specific exports keep their contracts; the public
additions are the Base UI/shadcn parts and their prop types,
`PhoneInputCountrySelectorRenderProps`, `PhoneCountryTriggerContent`,
`PhoneCountryTriggerState`, `PhoneCountrySearchAliases`, the optional
`triggerLabel` message and the `./locales/ja` export. The supported
metadata preset family remains **max, min, mobile, and validated custom
metadata**. Default paths retain max metadata; `/min` paths retain their
explicit `metadata.min.json` authority and entrypoint bundle budgets.

## Budgets

- `/base-ui` and `/shadcn`: 87,235 bytes gzip (+1.8 KB), within 88,000.
- `/base-ui/min` and `/shadcn/min`: 66,045 bytes gzip (+1.7 KB); their
  entrypoint bundle budget moves from 66,000 to 66,141 bytes, keeping 96 bytes
  of headroom.
- `/mui` +0.5 KB and `/headless` +0.2 KB gzip, within their budgets.
- The main executable closure budget moved from 33,506 to 34,023 bytes gzip
  (+517 bytes for the trigger content, trigger label and search aliases),
  keeping its 96-byte headroom.

The exact package passes the production Next.js 16 App Router and Vite
consumers without package-specific transpilation or server-externalization.
The verification apps now use Next.js 16.4.1 and Zod 4.6.6, the patched
releases required by the production dependency policy; the published library
does not depend on Next.js.

## Known limits

- Base UI 1.8 does not handle Home and End on a focused `PhoneCountryList`;
  they work from the search field.
- In the built-in popover Base UI moves focus to the search field on non-touch
  opens, so `autoFocusSearch` applies to `PhoneCountryList` only.
- `searchAliases` ship for Japanese only; other locales search by name, ISO code
  and calling code as before.
