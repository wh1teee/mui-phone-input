This is the **stable 1.0.2 patch release** of
`@wh1teee/mui-phone-input`. It contains the WebKit reconciliation correction
prepared for 1.0.1 and fixes the final source-harness resolution issue that
prevented 1.0.1 from reaching npm.

## Corrections

- Native selection offsets are reused only when the live DOM value belongs to
  the same authoritative formatted presentation. This prevents WebKit from
  pairing an advanced DOM caret with an older controlled display snapshot.
- The default max-metadata authority is now a normal relative source module.
  `/min` builds still substitute official `metadata.min.json` at compile time,
  but direct Vite/WCAG source consumers no longer depend on a build-only virtual
  specifier.

The fixes do not weaken transaction integrity, change controlled ownership, or
mix the max/min metadata graphs. Deterministic regression coverage passes in
Chromium, Firefox and WebKit. The source WCAG visual harness passes before tag
publication.

## Stable architecture retained

- MUI, headless, Base UI and shadcn remain independent renderer graphs.
- React Hook Form adapters remain explicit renderer subpaths.
- Default paths use max metadata; `/min` paths use the smaller official metadata.
- Exact-artifact bundle budgets include Maskito, `libphonenumber-js`, `tabbable`
  and selected metadata while excluding application-owned React/UI peers.
- Next.js 16 App Router and Vite exact-tarball consumers require no
  `transpilePackages`, `serverExternalPackages`, or experimental
  `optimizePackageImports` configuration.

The release is published through npm OIDC with immutable exact-artifact,
provenance, SBOM, registry-byte-parity, latest/minimum peer, WCAG and browser
verification.

Physical-device and assistive-technology evidence remains explicitly
`NOT_AVAILABLE`; the owner-accepted residual is recorded in `mpi-oan.24`.
Fresh exact-artifact RideOS validation came from merged RideOS PR #442. The
deferred Christofle item `mpi-oan.19` is unchanged. Stable patch publication and
npm `latest` promotion were explicitly authorized by the package owner on
2026-09-21.
