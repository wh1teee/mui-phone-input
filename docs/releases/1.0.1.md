This is the **stable 1.0.1 patch release** of
`@wh1teee/mui-phone-input`. It preserves the stable 1.0 public API and package
entrypoint architecture while fixing one native reconciliation race observed in
WebKit.

## WebKit reconciliation fix

A native input value and its selection now form one coherent snapshot. WebKit
can advance the live DOM value and caret before React runs the passive effect for
the previously rendered presentation. Selection offsets are therefore reused
only when `input.value` exactly equals the authoritative display value. If the
DOM has already advanced, reconciliation restores the authoritative value with
its own coherent end selection.

The fix does not clamp invalid offsets, weaken the transaction integrity guard,
change controlled ownership, or alter normal input/paste/composition
transactions. A deterministic browser harness reproduces the old interleaving
between commit and passive reconciliation. It passes in Chromium, Firefox and
WebKit after the fix.

## Stable architecture retained

- MUI, headless, Base UI and shadcn remain independent renderer graphs.
- React Hook Form adapters remain explicit renderer subpaths.
- Max metadata remains the default; `/min` entrypoints use official
  `metadata.min.json`. Max, min, mobile and validated custom metadata stay
  separately available.
- Entrypoint bundle budgets include Maskito, `libphonenumber-js`, `tabbable` and
  selected metadata, while excluding application-owned renderer/React peers.
  Exact-artifact CI continues to reject budget regression, metadata mixing and
  cross-renderer leakage.
- Next.js 16 App Router and Vite exact-tarball consumers continue to require no
  `transpilePackages`, `serverExternalPackages`, or experimental
  `optimizePackageImports` configuration.

The release is published through npm OIDC with immutable exact-artifact,
provenance, SBOM, registry-byte-parity, latest/minimum peer, WCAG and browser
verification.
