This is the **stable 1.1.0 minor release** of `@wh1teee/mui-phone-input`. It
makes country selection predictable in every renderer and adds configurable
popular countries. Existing imports, values and callbacks keep working; the
visible behavior changes are listed below.

## Country selection

- Search uses one shared ranking in MUI and Base UI/shadcn: an exact ISO code or
  the metadata's main country for a calling code first (`+1` → United States,
  `+44` → United Kingdom, `+7` → Russia), then other exact calling codes,
  prefixes and substrings. Previously Base UI kept alphabetical order, so `us`
  plus Enter could select another country.
- While a query is active, both renderers show one flat ranked list and
  highlight the best match. Previously MUI kept the highlight on the already
  selected country when it also matched.
- Without a query, preferred countries form a "Preferred countries" group above
  "All countries" in both renderers.
- The complete country list is the default. MUI previously stopped at 50
  options; `resultLimit` remains available and is now supported by Base UI.
- New `getPopularPhoneCountries(count)` returns the most populous countries for
  `preferredCountries`, with a configurable count.
- Choosing a country moves focus to the phone input; Escape and close still
  return focus to the trigger.
- The MUI mobile dialog list fills the available height. The Base UI trigger
  shows the calling code. The extension input is always left-to-right and the
  shadcn skin styles extension errors independently.

## Stable 1.0 compatibility retained

The stable 1.0 API remains compatible: React Hook Form (RHF), Zod, server,
locale, flag, and renderer-specific exports keep their contracts; the only
public additions are `getPopularPhoneCountries`, its parameter type, Base UI
`resultLimit` and the Base UI `group`/`groupLabel` class names. The supported
metadata preset family remains **max, min, mobile, and validated custom
metadata**. Default paths retain max metadata; `/min` paths retain their
explicit `metadata.min.json` authority and entrypoint bundle budgets.

The main executable closure budget moved from 32,636 to 33,103 bytes gzip for
the shared ranking and popular-country helper, keeping its 96-byte headroom.
The exact package passes the production Next.js 16 App Router and Vite
consumers without package-specific transpilation or server-externalization.
The verification apps now use Next.js 16.3.8, above the patched floor for
`GHSA-vcvr-r3jv-pc5j`; the published library does not depend on Next.js.

The fresh exact-artifact RideOS validation remains the previously merged RideOS
PR #442 evidence; this release has not been revalidated in RideOS.
Physical-device and assistive-technology evidence remains explicitly
`NOT_AVAILABLE`, as previously owner-accepted and recorded in `mpi-oan.24`.
The deferred Christofle item `mpi-oan.19` remains unchanged.
