This is the **stable 1.2.0 minor release** of `@wh1teee/mui-phone-input`. It
fixes issues found in an independent code review and stops repeating the
calling code in the country trigger.

## Fixes

- The country trigger shows the calling code only in national display mode;
  international modes already start the input with it. A dropdown chevron marks
  the MUI trigger. `PhoneInputState` exposes `displayMode`.
- The trigger follows the number: an explicit selection stays while its calling
  code matches, a different calling code shows the resolved country, and
  non-geographic numbers show no country.
- A `tel:` or extension-bearing paste can no longer replace a fixed calling
  code.
- A `+` Display Mask in national mode is rejected instead of changing the
  number.
- `extensionMaxLength` counts digits rather than typed separators.
- `parseRfc3966` rejects unknown mandatory `m-` parameters (RFC 3966 §5.4).
- MUI React Hook Form keeps consumer extension props without `extensionName`
  and binds custom-rendered extensions.
- Base UI/shadcn shows an application error's `helperText` and sizes flags.
- `/headless`, `/base-ui` and `/shadcn` export shared formatting and state types.

## Stable 1.0 compatibility retained

The stable 1.0 API remains compatible: React Hook Form (RHF), Zod, server,
locale, flag, and renderer-specific exports keep their contracts; the public additions are
`PhoneInputState.displayMode` and shared formatting/state types on `/headless`,
`/base-ui` and `/shadcn`. The supported
metadata preset family remains **max, min, mobile, and validated custom
metadata**. Default paths retain max metadata; `/min` paths retain their
explicit `metadata.min.json` authority and entrypoint bundle budgets.

The main executable closure budget moved from 32,636 to 33,358 bytes gzip for
the shared ranking and popular-country helper, keeping its 96-byte headroom.
The exact package passes the production Next.js 16 App Router and Vite
consumers without package-specific transpilation or server-externalization.
The verification apps now use Next.js 16.3.8, above the patched floor for
`GHSA-vcvr-r3jv-pc5j`; the published library does not depend on Next.js.

The fresh exact-artifact RideOS validation remains the previously merged RideOS
PR #442 evidence; this release has not been revalidated in RideOS.
Physical-device and assistive-technology evidence remains explicitly
`NOT_AVAILABLE`, as previously owner-accepted and recorded in `mpi-oan.24`.
The deferred Christofle item `mpi-oan.19` remains unchanged.
